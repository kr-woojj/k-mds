## 과제 고정 정보  (불변 블록. 기준: 3차년도 수정사업계획서 2026-05-15)
### 사업 체계
- 부처/전담기관: 산업통상부(과제 문서 표기는 "산업통상자원부") / 한국산업기술기획평가원(KEIT)
- 사업: 조선해양산업기술개발사업 > 조선해양산업핵심기술개발, 공고 제2024-415호, 지정공모
- 과제 특성: 원천기술형, 신산업창출형, 표준연계, 초격차, R&D 자율성트랙(일반), 기술료 징수, 일반(비보안) 과제
- TRL 3 → 5. RFP 핵심기술요소: 데이터 표준 TRL5(결과물 국제표준 문서, 평가환경 국제 표준화) /
  서비스 3건 TRL4(결과물 서비스 설계도, 평가환경 수요기관 평가)
- 기간: 전체 2024-07-01 ~ 2027-03-31 (33개월, 1단계) /
  1차 2024-07-01~2025-03-31, 2차 2025-04-01~2026-03-31, 3차 2026-04-01~2027-03-31

### 최종 목표
조선해양산업의 데이터 연계 비즈니스 생태계를 위한 데이터 주권 확보와 안전하고 신뢰할 수 있는
데이터 상호운용성 확보를 위한 스마트·자율운항선박 밸류체인 간 데이터 표준 개발 및 서비스 설계
- RFP 정량 목표(최종평가 기준선): ①데이터 표준 개발 1건 ②데이터 표준 가이던스 국제표준화 1건(ISO/IEC 등 기고 이상)
  ③데이터 품질관리 지침 1건 ④데이터 표준 기반 서비스 설계 3건 ⑤상호운용 검증 평가 기술 1건
- 3차년도 목표: 기술 "검증" 단계. 공유 기술·보안 검증 / ISO 국제표준 기고 / 품질관리 지침 개발 / 서비스 수요기업 평가

### 컨소시엄과 3차년도 담당 (산출물)
- 주관 한국선급: 과제 총괄, RFP4-3 환경규제 보고 데이터 표준기반 서비스 API 개발 (개발서 1부)
- 한국조선해양기자재연구원(KOMERI): RFP2 ISO 국제표준 기고 (표준화 1건). TC8 COSD
- 중소조선연구원(RIMS): RFP4-4 포트콜 서비스 API 개발·평가 시나리오 적용 (개발서 1부),
  RFP5 시뮬레이터 기반 서비스 평가·상호운용 검증 (평가서 1부)
- 한국해양대학교 산학협력단: RFP3-1·3-2 품질관리·보안관리 요구사항 (지침서 각 1건)
- 랩오투원: RFP1 데이터 공유방법·보안방법·운용방안 개발 (보고서 1건)
- 케이엘넷: RFP4-1·4-2 실증 시나리오·경제모델 (명세서 1부), RFP4-5 선박 의무보고 서비스 (개발서 1부)
- 유엔젤: RFP3-3 통합 테스트, 데이터 공유 개념 모델 설계서 v1.0 (평가서 1부)
- 수요기업(공동연구개발기관으로 참여): HD한국조선해양, 삼성중공업, 한화오션(조선) /
  부산항만공사, 울산항만공사(항만) / 팬오션, 포스에스엠(해운). 수요기업 평가와 자문 담당
- 위탁연구개발기관: 없음

### KR 담당 범위
- 계획서 문구: 환경규제 보고 관련 데이터 표준 기반 신개념 서비스 설계(RFP4-3).
  1차 요구사항 정의 → 2차 데이터 표준 개발 → 3차 서비스 API 개발 및 검증
- 계획서가 명시한 대상: 규제 제도 IMO DCS, EU MRV / 선급 지침 SEEMP, EEXI, CII 검증 지침 /
  국제표준 ISO 19848, ISO 18131 / 단체 표준(선사·시스템 제공업체 운항 데이터).
  벙커링·충전 데이터와 그 이해관계자(벙커링/충전 사업자, 보험사)까지 고려
- 수행 중 채택한 참조 모델(2차 연차보고서): IMO Compendium 데이터 요소(IMO번호),
  SMN SVD, Energy LEAP VERS, KR GEARs. 이들은 계획서 문구가 아니라 실적이다
- 2차년도 결과물: 7개 데이터 그룹(Ship / Voyage / Weather / Cargo / ROB / Fuel Consumption /
  Power Consumption), IMO DCS 및 UK·EU MRV 필수·부가 항목 구분, CSV·JSON 스키마,
  RESTful OpenAPI 명세, ER 다이어그램. 자체평가 94.4점(외부전문가 5명)
- 3차년도 일정 항목(주): 표준연계 실증 시나리오 개발(24) / 표준 인터페이스(API) 개발(16) /
  시뮬레이션 기반 표준 모델·스키마 검증(24) / 빅데이터 기반 클라우드 서비스 설계(16) /
  AI 활용이 가능한 분석 서비스 설계(16)
- "AI Agent 서비스"는 위 마지막 두 항목의 구현 형태다. 과제 문서에는 이 용어가 없으므로
  보고서·발표 자료에서는 계획서 문구에 대응시켜 쓴다

## 문서 우선순위
같은 항목이 문서마다 다르면 아래 순서로 기준을 정하고, 다른 판의 값은 "이력"으로만 쓴다.
1) 목표·산출물·예산·일정: 3차년도 수정사업계획서(2026-05-15) > 2차년도 수정사업계획서 > 협약용 계획서
2) 2차년도까지의 실적: 2차 연차보고서(2026-03-20). 1차년도 실적은 1차 연차보고서
3) RFP·공고: 과제의 최소 요구와 근거 규정 목록. 최종평가의 기준선으로 따로 유지한다
4) 현재 시점 실적·집행액: get_kpi_status, get_budget_status. 문서의 수치로 대체하지 않는다
주의: 2차 연차보고서 5-5의 "다음 연도 연구개발비"는 감액 전 계획이다. 3차년도 예산 근거로 쓰지 않는다.
협약 변경 공문 등 위 문서보다 나중 자료가 저장소에 있으면 그것이 우선하며, 발견 시 사용자에게 알린다.
